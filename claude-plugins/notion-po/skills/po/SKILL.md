# 개발팀 PO 보조 (Notion)

Circularlabs 개발팀의 스크럼 운영을 Notion 에서 보조한다.

- 리소스 ID·속성 맵·실행 규칙은 [notion-resources.md](../../references/notion-resources.md) 가 단일 출처다. 작업 전에 읽는다.
- 조회·쓰기는 `bun ${CLAUDE_PLUGIN_ROOT}/scripts/ntn.ts` 로 한다. 이하 `ntn.ts` 로 줄여 쓴다.
- 필요한 도구: `bun`, `ntn` CLI. 작업 전 `ntn whoami < /dev/null` 로 인증을 확인한다. 실패하면 마스터에게 `! ntn login` 을 요청하고 멈춘다.
- 스크럼 운영 원칙(이벤트, WSJF, 벨로시티, 긴급 건)의 근거는 [scrum-playbook.md](../../references/scrum-playbook.md). 점수 척도는 `1/2/3/5/8` 만 쓰고 플레이북의 `13/20` 은 쓰지 않는다. 그보다 크면 작업을 나눈다.

## 스프린트 제목 형식

```
[{시작일 YYMMDD}-{종료일 YYMMDD}]{백로그들 요약}
```

- 날짜는 `기간` 의 start/end 를 `YYMMDD` 로 줄인다. 구분자는 `-`, 닫는 대괄호 뒤 공백 없음.
- 예: `[260727-260809]카페 선결제·EasyPay 도입과 매출·정산 현황 개선`

## 백로그 이월 규칙

"이 백로그 다음 스프린트로 옮겨줘" 같은 요청도 그대로 옮기지 않고 이 규칙을 따른다.

- **이전 스프린트 백로그의 `⚡ 스프린트` relation 은 바꾸지 않는다.** relation 은 1개 제한이라 옮기면 원 스프린트의 WIP 기록이 사라진다.
- **미완료 작업은 신규 백로그로 이월한다.**
    - 원본 `지연사유` 속성에 왜 못 끝냈는지와 어디로 이월했는지를 쓴다.
    - 신규 백로그를 만들어 새 스프린트에 연결하고, 본문 `## 참고` 에 원 항목 링크를 남긴다.
- 상태별 기본 처리
    - `스테이징`: 이월하지 않는다. 검증만 남은 단계라 원 스프린트에서 마무리하는 게 팀 전례다.
    - `진행 중`: 잔여만 분리해 신규 백로그를 만들고 backlog-scoring rubric 으로 재스코어링한다.
    - `스프린트`(미착수): 점수 4종·가치판단·에픽·작업자를 그대로 복제한다.

마스터가 규칙에 어긋나는 이동을 요청하면 이 규칙을 알리고, 이월 방식으로 진행할지 확인한다.

## 스프린트 생성 — `sprint init {N}`

가장 가까운 다가오는 월요일부터 N주간의 빈 스프린트(제목+기간)를 만든다. 백로그 연결·상태 설정은 하지 않는다.

- **N**: `1`~`4` 정수. 벗어나면 실행하지 않고 알린다.
- **기간**: 오늘 이후 가장 가까운 월요일(오늘이 월요일이면 오늘)부터 `start + (N*7 - 1)`일까지. 월~일, 양끝 포함.
    - 예: 2026-10-05(월)에 N=2 → `2026-10-05 ~ 2026-10-18`. 2026-10-06(화)에 N=2 → `2026-10-12 ~ 2026-10-25`.

절차:

- 단계 1 — 날짜 계산: `ntn.ts sprint-dates {N}`. 결과의 `start`·`end`·`title`(placeholder 제목)을 쓴다. 날짜를 손으로 계산하지 않는다.
- 단계 2 — 중복 확인: `ntn.ts sprints` 에 같은 시작일이 있으면 만들지 않고, 알린 뒤 계속할지 묻는다.
- 단계 3 — 생성: Write 도구로 바디 파일을 쓰고 `ntn.ts write /v1/pages POST <파일>` 을 실행한다. 본문 블록은 만들지 않는다.

  ```json
  {
    "parent": {"type": "data_source_id", "data_source_id": "3a3f68d9-4082-807e-8a43-000b9965f503"},
    "properties": {
      "이름": {"title": [{"text": {"content": "<title>"}}]},
      "기간": {"date": {"start": "<start>", "end": "<end>"}}
    }
  }
  ```

- 단계 4 — 보고: 제목·기간·응답 `url`.

생성은 `ntn pages trash <page-id> --yes` 로 되돌릴 수 있다. 부모는 위 스프린트 data source 로 고정한다.

## 스프린트 제목 정리 — `sprint update`

어느 스프린트인지 먼저 묻고, 연결된 백로그를 근거로 한 줄 제목을 지어 `이름` 을 교체한다.

- 단계 1 — 스프린트 선택: `ntn.ts sprints` 목록을 기간 순으로 보여 주고 `AskUserQuestion` 으로 고르게 한다. "이번 스프린트" 라고 하면 `ntn.ts current-sprints` 의 `current` 가 1순위 후보다.
- 단계 2 — 백로그 수집: `ntn.ts backlog --sprint <SPRINT_PAGE_ID>`. `취소` 항목은 제외한다. 공통 테마가 필요하면 `에픽` relation 을 `ntn pages get` 으로 확인한다.
- 단계 3 — 제목 생성: 개별 작업 나열이 아니라 스프린트의 테마를 30자 안팎 명사구로 요약하고 날짜 접두를 붙인다. 백로그가 한 에픽에 쏠려 있으면 그 에픽을 축으로 한다. 백로그가 비어 있으면 제목을 만들지 않고 "연결된 백로그가 없어요" 라고 알린다.
- 단계 4 — 확인 후 교체: 새 제목을 보여 주고 승인받는다. 기존 제목을 보고에 남긴 뒤 Write 도구로 `{"properties": {"이름": {"title": [{"text": {"content": "<새 제목>"}}]}}}` 를 쓰고 `ntn.ts write /v1/pages/<SPRINT_PAGE_ID> PATCH <파일>` 을 실행한다.
- 단계 5 — 보고: `이전 제목 → 새 제목`, 스프린트 URL, 근거 백로그 개수.

이 절차는 스프린트 `이름` 만 바꾼다. 백로그 상태·포인트는 건드리지 않는다.

## 실측 기록

- 2026-08 기준, 보드의 옛 스프린트 일부는 월~월(예: `2026-07-27 ~ 2026-08-03`, 8일)로 종료일을 다음 주 월요일에 뒀다. 현재 규칙은 마스터가 확정한 월~일이다. 팀 관행(월~월)에 맞추라는 지시가 오면 종료일을 `start + N*7` 로 바꾼다.
